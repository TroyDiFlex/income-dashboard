# Разработка Потока

[← README](../README.md)

## Файлы

| Файл | Назначение |
| :--- | :--- |
| `index.html`, `style.css`, `theme-head.js` | Интерфейс, адаптивная вёрстка, шесть тем и синхронизация оформления иконок. |
| `app.js` | Навигация, формы, фильтры и представление аналитики. |
| `model.js` | Валидация и расчёты. В клиентской модели суммы хранятся в копейках. |
| `chart.js` | Геометрия и анимация SVG-графиков. |
| `api.js`, `config.js` | Клиент API, сессия и публичные настройки подключения. |
| `pwa.js`, `manifest.webmanifest` | Установка приложения. Офлайн-кэширования нет. |
| `server/Code.gs` | Google Apps Script: авторизация, чтение, запись, корзина. |
| `tests/` | Проверки расчётов, интерфейсных контрактов и серверной логики. |
| `scripts/capture-readme.mjs` | Съёмка галереи с вымышленными данными. |

Для самого приложения не нужны npm-зависимости, сборщик или серверный Node.js. Файлы интерфейса можно отдавать статическим HTTP-сервером. Вход и данные требуют настроенного Google Apps Script; локальная копия с текущим `config.js` обращается к указанному в нём серверу.

Для просмотра с тестовыми данными используйте [сценарий съёмки](screenshots/README.md): он запускает приложение локально и обрабатывает API-запросы в памяти.

## Проверки

Из корня репозитория:

```sh
node --test tests/*.test.mjs
```

Тесты корзины используют вымышленные данные и управляемые часы. Проверяются граница 30 дней, восстановление, повторное удаление, конфликты, отсутствие доступа и сбои записи.

## Источники и корзина

Настройки источника открываются нажатием на его название в таблице или форме «По месяцу». Неактивные источники остаются в расчётах. Удаление перемещает источник со всеми доходами в корзину на 30 дней; до восстановления они исключены из аналитики. Окончательное удаление требует отдельного подтверждения с задержкой 3 секунды.

Время удаления хранится в закрытых свойствах серверного проекта. Перемещение и восстановление не меняют ячейки Google Таблицы. Очистка удаляет только строки просроченных источников и их доходов, сохраняя остальные ячейки и оформление.

Срок хранения — 30 × 24 часа по серверному времени. Фоновая очистка запускается каждый час. Чтение и сохранение также проверяют срок, поэтому просроченный источник восстановить нельзя даже при задержке фонового запуска.

## Сервер и обновление

Веб-приложение Google Apps Script выполняется от имени владельца. Для данных нужны вкладки `Источники` и `Доходы`, а в закрытых свойствах проекта — `SPREADSHEET_ID`, `AUTH_SALT` и `AUTH_HASH`. Формат проверки пароля описан в начале [Code.gs](../server/Code.gs); пароли, ключи и финансовые записи не должны попадать в публичные файлы.

Код Apps Script обновляется через **clasp или официальный Apps Script API из консоли**. Редактирование и публикация через браузер для этого проекта запрещены.

В рабочей копии владельца установлен и авторизован clasp 3.4.1. Из корня репозитория:

```powershell
.local/clasp.ps1 push
.local/clasp.ps1 update-deployment <ID_действующего_развёртывания>
```

Перед отправкой проверьте изменения. ID берётся из URL `apiUrl` в локальном `.local/deployment.json`. Обновляйте существующее веб-приложение; не создавайте новое развёртывание вместо него. Сетевым командам clasp нужен доступ вне песочницы. Локальный wrapper и учётные данные не входят в репозиторий и не появятся при обычном клонировании.

После первого обновления с поддержкой корзины серверу требуется разрешение `script.scriptapp` для фонового запуска. Авторизованный запрос `trashMaintenance` устанавливает один часовой триггер `purgeExpiredSources` и проверяет срок хранения. Перемещение в корзину тоже проверяет наличие триггера и не меняет данные при ошибке его установки.

Если доступ через консоль недоступен, подготовьте код и короткую инструкцию для ручного обновления владельцем.

## Локальные файлы

Резервные копии, учётные данные и результаты локальных проверок хранятся в исключённой из Git папке `.local/`. Не выводите и не коммитьте `.local/clasprc.json`.

В `docs/screenshots/` публикуются только специально созданные вымышленные данные и снятые с ними изображения. Сценарий не читает рабочую таблицу, сохранённые сессии или резервные копии.
